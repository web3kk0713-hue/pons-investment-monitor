# PONS 每日投资监控：指标合同

本看板每天更新一次，但保留 7 日、30 日和相邻窗口对比。页面将事实、推导值、历史基线和缺失数据分开，不用估算值填补缺口。

## 决策门槛

只有价值捕获、留存、安全、流动性四个维度同时改善，且关键指标覆盖率达到 85%，状态才可从“事件驱动观察”升级为“基本面配置”。任一维度未知都不能升级；出现重大权限变更、安全事故或流动性骤降时，直接降为“风险降级”。

## 核心指标

| 维度 | 每日采集、滚动观察 | 判定重点 |
|---|---|---|
| 价值捕获 | V1/V2 7日与30日协议收入、费用、创作者收入、真实 PONS 死地址增量、待执行回购资金、回购收益率、收入年化估值倍数 | 区分“平台赚钱”和“PONS 持有人受益” |
| 留存与质量 | 独立 creator、复发率、毕业率、毕业项目 D7 留存、曲线/毕业后成交、Pons 与 Pools.trade 发行和成交份额 | 用户和项目质量是否脱离事件热度 |
| 安全与治理 | Owner、Hook owner、sweep operator、费率策略变化，审计状态、地区限制、数据源漂移 | 是否出现可改变资金流或规则的未预期权限变化 |
| 流动性与市场风险 | 现货/合约正负2%深度、Top10 项目成交占比、PONS 池流动性、资金费率、未平仓量、基差 | 能否在不显著冲击价格的情况下进出 |

## 新增投资指标

| 指标 | 用途 | 当前采集等级 |
|---|---|---|
| 市值 / 年化30日协议收入 | 衡量市场为协议现金流支付的倍数 | 自动 |
| 市值 / 年化持币人收入 | 衡量代币直接价值捕获估值 | 自动或部分 |
| V2 收入占比与 PONS 捕获差 | 识别“业务增长、代币不受益” | 自动 |
| 待回购资金 / 30日协议收入 | 判断回购执行积压 | 自动 |
| 死地址日增量及其美元价值 | 检查实际通缩是否发生 | 自动，归因需谨慎 |
| 持币地址、Top10/Top50 集中度 | 识别筹码风险 | 浏览器/API恢复后自动；当前缺失 |
| 大额转账和交易所净流 | 识别鲸鱼/潜在卖压 | RPC部分自动；地址标签需外部数据 |
| 资金费率、OI、基差、清算 | 识别杠杆拥挤 | 资金费率/OI自动；清算缺失 |
| Robinhood Chain 活跃度和 PONS 依赖度 | 判断单链生态依赖 | 部分自动 |
| 数据新鲜度、覆盖率、源间偏差 | 防止用异常或过期数据投资 | 自动 |

## 口径约束

- “死地址新增”不自动等同于“协议回购销毁”；只有能追溯到已知回购执行路径才标记为已验证回购。
- V2 回购 V2 项目代币，不应计入 PONS 持有人收入。
- 创作者收入可由协议费用减协议收入推导时标记为“推导”，不是官方直接字段。
- Pools.trade 发行数使用其 TokenCreated 事件；Pons 发行数来自官方分析接口。两者时间窗口必须一致后才计算份额。
- 现货与永续盘口分别展示，合并深度仅作流动性压力参考。
- GitHub 运行器的地区访问结果只代表探测地点，不代表全球监管合规。
